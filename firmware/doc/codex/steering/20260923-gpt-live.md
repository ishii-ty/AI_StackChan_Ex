# OpenAI GPT-Live Support (Realtime AI Service)

## 目的

`REALTIME_API` ビルドの Realtime AI Service に OpenAI GPT-Live（`gpt-live-1`）を追加する。
既存の OpenAI Realtime（`LLM_TYPE_CHATGPT`）・Gemini Live（`LLM_TYPE_GEMINI`）の実装は変更せず、設定ファイル／Web UI の Service 選択で切り替えられるようにする。
GPT-Live のモデル、委譲先（バックエンド）モデル、voice は、設定ファイルと Web UI（Config > AI Service）の両方から指定できるようにする。

## GPT-Live 仕様の要点（2026-09-23 調査）

- 接続: `wss://api.openai.com/v1/live/sessions`、ヘッダ `Authorization: Bearer <API key>`。接続後、最初に `session.start` を送り、`session.started` を受けて開始。
- `session.start` の `session`: `model`、`instructions`、`audio.format`、`audio.output.voice`、`delegation`。
- 音声フォーマットは入出力共通で、開始後は変更不可。`audio/pcm` 24000 / 16000、`audio/pcmu` / `audio/pcma` 8000。
- 入力 `session.input_audio.append`（base64、ACK なし）／出力 `session.output_audio.delta`（base64）。WebSocket では `output_audio.done` も `response.done` もない。
- 文字起こし: `session.input_transcript.delta` / `session.output_transcript.delta`。
- マイク制御: `session.input_audio.mute` / `unmute` → `session.input_audio.muted` / `unmuted`。mute 中もセッションは継続し、モデルが話し続けることがある。
- 終了: `session.close` → `session.closed`（`usage`、`reason`。duration limit による終了もある。上限の具体値は非公開）。
- 課金: 接続時間に対して $0.05/分（秒単位）。委譲先モデルとツールの料金は別。公式も、無操作の間はセッションを閉じ、利用者が戻ったら新しいセッションを開始するよう推奨している。
- ツール（Responses 委譲）: `delegation: {type:"responses", responses:{model, instructions, tools, tool_choice}}`。function 呼び出しは `response.event`（内側 `event.type == "response.output_item.done"`、item が `function_call`）で届く。結果は `response.item.create`（`function_call_output`）と `response.create` で返す。
- 割り込み（barge-in）時に再生停止を指示するサーバーイベントは WebSocket 向けには定義されていない。
- 非対応: 画像／動画入力、TTS と組み合わせる half-cascade（`REALTIME_API_WITH_TTS`）。

## 実装方針

### 1. 切り替え

- `StackchanExConfig.h` に `#define LLM_TYPE_GPT_LIVE 5` を追加する。
- `Robot::initRtLLM()` に `case LLM_TYPE_GPT_LIVE: llm = new GptLive(llm_param);` を追加する。
- `REALTIME_API_WITH_TTS` と GPT-Live は併用できないため、`WITH_TTS` ビルドで type 5 が指定された場合は、警告ログを出して OpenAI Realtime（`RealtimeChatGPT`）にフォールバックする。（当初は `llm = nullptr` としていたが、`RealtimeAiMod` が起動直後に null 参照で落ちるため、Codex レビューの指摘を受けて変更）
- Mod 切替でタスクを止める前に、GPT-Live のセッションを閉じる（`beforeSuspend()` フック）。止めたままだと、接続時間で課金されるセッションが開いたままになるため（Codex レビューの指摘）。

### 2. 設定

- Ex YAML の `llm` 配下に GPT-Live 専用キーを追加する。
  - `llm.liveModel`: GPT-Live モデル（空欄なら `gpt-live-1`）
  - `llm.delegationModel`: Responses 委譲先モデル（空欄なら `gpt-5.6-luna`）
  - `llm.liveVoice`: GPT-Live の voice（空欄なら `marin`）
- 既存の `llm.model`（ChatGPT type 0 / Custom OpenAI type 4 用）は流用しない。非 Realtime ビルドに戻したとき、`gpt-live-1` が ChatGPT のモデル名として使われないようにするため。
- `llm_s` 構造体にフィールドを追加し、`setExtendSettings()` で読み込む。

### 3. Web UI

- Service の選択肢に `<option value="5">OpenAI GPT-Live</option>` を追加する。
- AI Service パネルに「Live Model」「Delegation Model」「Voice」のテキスト入力を追加する。Service が GPT-Live のときだけ表示する。空欄なら既定値を使う（プレースホルダに既定値を表示）。
- `config.js`: `applyConfig()` の `llm.type === 3 ? 3 : 0` を、許可 type（0/3/5）の判定に変える。保存 payload に上記キーを含める。
- `WebAPI.cpp`:
  - `GET /config` は上記キーを返す。SPIFFS 読込時と `ex_config` フォールバック時の両方で、type 5 も許可する（`WebAPI.cpp:832` の判定）。
  - `POST /config` の `merge_extend_settings()` は上記キーだけを上書きする。既存のマージ方式を踏襲し、`llm.model` など他のキーは保持する。

### 4. GptLive クラス（`RealtimeLLMBase` 派生）

- 音声フォーマットは `audio/pcm` 16000Hz にする。マイク録音（`RT_REC_SAMPLE_RATE` = 16000）とそろえ、変換処理を不要にする。出力も 16kHz で再生する。
- **セッションのライフサイクル**（常時接続しない）
  - 起動時は接続しない。吹き出しは「Please touch」。
  - タッチ（`startRealtimeRecord()`）→ WebSocket 接続 → `session.start` → `session.started` を受けて録音を開始し、「Listening...」を表示。
  - 終了条件は次のどちらか。どちらも `session.close` を送り、`session.closed` を受けたら切断する。
    - **タイマー**: 最後の活動（入力／出力の transcript delta、出力音声の受信・再生、関数呼び出し。ローカルの振幅判定は雑音でも反応するため含めない）から、無操作タイムアウト 30 秒（ファームウェアの定数。設定項目にはしない）を超えた。
    - **画面タッチ**: 会話中（録音中または発話中）に吹き出し領域をタッチした（既存の `toggleRealtimeRecord()` → `stopRealtimeRecord()`）。
  - `session.closed` を duration limit など想定外の理由で受けた場合も切断し、「Please touch」に戻す。
  - WebSocketsClient は切断後も `loop()` を呼ぶと自動で再接続するため、セッション外では `loop()` を呼ばないようにする（下記 5 のフック）。
- **疑似半二重**（Core2 / CoreS3 / Echo Base は M5Unified で Mic と Speaker を同時に使えない）
  - 応答音声を受け取ったら `session.input_audio.mute` を送り、Mic を止めて Speaker で再生する。既存と同じく `enterMutexAudio()` で保護する。
  - （2026-09-23 実機確認で追記）GPT-Live は無音の出力音声も常時流すため、出力 delta のピーク振幅で声の有無を判定し、声の入ったチャンクだけを応答として扱う。無音チャンクでは無操作タイマーを延長しない。
  - 応答の終わり: 最後の `output_audio.delta` から一定時間（初期値 600ms 程度）受信がなく、Speaker の再生も終わった時点で終わりとみなす。`unmute` を送り、録音を再開する。
- **相槌の扱い**（再生せず吹き出しに表示）
  - ユーザーの発話中にモデルの音声が届いた場合は、相槌とみなす。
  - 発話中かどうかの判定は、録音バッファの振幅（ローカルの簡易 VAD）で行う。直近の一定時間（初期値 500ms 程度）内に閾値を超えていれば発話中とする。transcript は音声より遅れて届くため、判定には使わない。
  - 相槌と判定したら、その音声 delta は捨てる（Mic は止めない）。同じ区間の `session.output_transcript.delta` を吹き出しに表示する（例:「うんうん」）。
  - 閾値・時間は定数にし、実機で調整する。判定を誤ると、応答の冒頭が欠けたり、相槌が再生されたりする（残リスク）。
- **Function Calling**（Responses 委譲）
  - `delegation.responses.tools` に、`json_Functions`（`FunctionCall.cpp`）と接続中の MCP ツール一覧を `type:"function"` として設定する。既存 `RealtimeChatGPT` の `session.update` 組み立て処理と同じやり方。
  - `response.event` の内側 `response.output_item.done`（`function_call`）を受けたら、`fnCall->exec_calledFunc()` を実行する。結果を `response.item.create` と `response.create` で返す。
  - instructions の分割:
    - `session.instructions` = role + userInfo（会話のキャラクター・記憶）
    - `delegation.responses.instructions` = systemRole（関数の使い方の方針。memory、表情変更など）
  - `load_role()` をセッション開始のたびに呼び、`update_memory` の結果が次のセッションに反映されるようにする。
- voice は `llm.liveVoice` から設定する（空欄なら `marin`）。
- 受信 JSON 用の `msgDoc`（150KB）と `WEBSOCKETS_MAX_DATA_SIZE`（150KB）は既存と同じ値で足りる想定。16kHz なので delta は 24kHz より小さい。

### 5. RealtimeLLMBase の拡張（既存クラスの動作は変えない）

- 再生サンプルレートをメンバ（既定 24000）にし、`streamAudioDelta()` のハードコードを置き換える。GptLive は 16000 を設定する。
- `webSocketProcess()` に、既定では何もしない仮想フックを追加する。
  - WebSocket を処理するか（既定 true。GptLive はセッション外で false を返し、自動再接続を防ぐ）
  - 録音チャンクを送った後の処理（GptLive の VAD と無操作タイマー用）
  - 待機中・録音中の吹き出し文字列（既定は現状の「Please touch」「Listening...」。GptLive は相槌の表示中に上書きさせない）
- `startRealtimeRecord()` / `stopRealtimeRecord()` を virtual にする。GptLive はセッション接続／終了処理を追加し、その上で基底を呼ぶ。

## 設計上の注意点

- 課金事故を防ぐことを最優先にする。セッションが開きっぱなしにならないよう、無操作タイマーはセッションの状態によらず常に動かす。WebSocket 切断を検知したら状態をリセットする。
- 疑似半二重のため、GPT-Live の割り込み（barge-in）はこの実装では使えない。再生中は Mic が止まるため。今の OpenAI Realtime と同じ制約。
- 委譲は非同期に実行されるため、表情変更などの関数実行は発話より遅れることがある。
- Web UI のマージ保存では、YAML のコメントは保持されない（既存仕様どおり）。
- API キーなどの秘密情報はコード・ドキュメントに含めない。
- タスクは追加しない（既存の `webSocketLoopTask` で処理する）。ヒープの増加は GptLive インスタンス分だけ。

## 決定事項（2026-09-23 ユーザー確認済み）

- 設定キー: `llm.liveModel` / `llm.delegationModel` / `llm.liveVoice` を新設する（`llm.model` は流用しない）。
- Web UI: Live Model、Delegation Model、Voice の3項目を指定できるようにする。無操作タイムアウトは Web UI にも設定ファイルにも出さない。
- 無操作タイムアウト: 30 秒。
- 委譲先モデルの既定値: `gpt-5.6-luna`。
- 会話の終了: タイマー判定と画面タッチ。
- 相槌: 再生せず、吹き出しにテキストを表示する。

## 確認方法

- ビルド: `m5stack-core2-realtime`、`m5stack-cores3-realtime`、`m5stack-atoms3r-realtime`。
- 回帰: type 0（OpenAI Realtime）と type 3（Gemini Live）で、従来どおり会話・関数呼び出し（表情変更）ができること。
- GPT-Live（type 5）:
  - 起動時に接続しないこと（シリアルログで WebSocket 未接続を確認）。
  - タッチ → 接続 → 会話 → 応答の再生 → 録音再開が回ること。
  - 相槌が再生されず、吹き出しに表示されること。
  - 無操作タイムアウトと会話中のタッチで `session.close` → `session.closed` → 切断となり、再接続しないこと。
  - 「表情を変えて」「3分タイマー」などで関数呼び出しが実行されること。MCP サーバーが設定されていれば MCP ツールも呼べること。
  - `session.closed` の `usage` をログに出し、課金対象の時間が会話時間に見合っていること。
- Web UI: Service = GPT-Live とモデル・Voice を保存 → Restart で反映されること。他の Service に切り替えても `llm.liveModel` / `llm.delegationModel` / `llm.liveVoice` が保持されること。

## 戻し方

`LLM_TYPE_GPT_LIVE` の case、`GptLive.*`、Web UI の選択肢を削除する。`RealtimeLLMBase` のフックは既定動作が現状どおりなので、残しても既存機能に影響しない。設定ファイルに追加したキーは、他の type では参照されないため残っていても無害。
